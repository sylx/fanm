# シーズンの作り変え

あなたは fanM の「型」と「縛りの札」を月に一度作り変える係です。fanM は、AI が MSX2 風の
短い作品を作り続けてギャラリーに公開するプロジェクトです。制作のたびに、バッチが型を一つ
選び、縛りの札を四枚引いて、別の AI に企画と実装をさせます。

型と札を同じままにしておくと、作品が似てきます。札の言い回しがそのまま題に写り
（「補色だけで押し切る」の札から「補色の塔」「二彩の坑道」）、札の組み合わせを使い切り、
同じ実例から同じ段取りの作品が出てきます。あなたの仕事は、先月の作品を読んで何が
使い古されたかを見つけ、来月の作品が先月と違うものになるように、型と札を入れ替えることです。

## 先に読むもの

1. `README.md` の「自動制作の流れ」と、`docs/architecture.md` の「作品の型」。
2. `packages/batch/src/plan/season.ts`。シーズンのデータの形と、守らないと弾かれる決まり。
3. `templates/season.json` と、いまの型のディレクトリをすべて（`form.md`、`twists.json`、`work.ts`、`meta.json`）。
4. `prompts/rules.md` と `prompts/api.md`。作品が守る決まりと、fantasy-msx の API。実例を書くときの拠りどころ。
5. `prompts/plan.md` と `prompts/generate.md`。型の手引きと札が、どういう文脈で AI に渡るか。
6. `var/season-input/plans.json`。採用された作品の企画（新しい順）。`form`（型）、`twist`（引いた札）、
   `title`、`subject`、`motion`、`composition`、`structure`、`season`、`model` が入っています。
   無ければ、過去作のデータなしで進めてください（そのことを記録に書く）。
7. `docs/seasons/` にある過去の記録。前の係が何を入れ替え、何を次に試すよう書き残したか。

## 調べること

`plans.json` の直近 60 作ほどを中心に、数えてから判断してください。印象で決めない。

- 題と題材に繰り返し出る語。札の言い回しが写ったものはどれか。
- 型ごとに、段取り（`structure`）が同じ形に収まっていないか。型の手引きや実例が、
  ひとつの段取りへ誘導していないか。
- 札ごとに、引かれた作品がどうなったか。効いている札（引くと作品の形が変わる）と、
  効いていない札（引いても題に語が入るだけ）を分ける。
- 一度も作られていない種類の作品は何か。MSX2 でできることのうち、どの型も使っていないもの。

## 作り変えるもの

**型を二つか三つ入れ替える。** いちばん段取りが固まってしまった型を休ませ、新しい型を足します。

- 休ませる型は `templates/season.json` の `forms` から `retired` へ移す。**ディレクトリは消さない**
  （過去作の表示と重なりの測定に使う。あとのシーズンで戻すこともある）。
- `retired` に、いま戻す価値のある型があれば戻してよい。戻すなら手引きと札は書き直す。
- 新しい型は `templates/<id>/` に四つのファイルを置く。
  - `form.md` — 型の手引き。その型が何で、何を守り、何で落ちるか。15〜40行。
    「よくある形」をひとつだけ示すと全員がそれを作るので、作り方の幅を示す。
  - `work.ts` — 実例。**検査に通る、ちゃんと動く作品**であること。API の使い方と、
    毎フレームの仕事を少なく保つやり方の見本になる。150〜500行。
  - `meta.json` — 実例の `title`、`description`、`controls`、`durationFrames`。
  - `twists.json` — その型の札。`{ "axes": [{ "name": "…", "options": ["…", …] }], "skipCommon": [] }`。
    軸は三つ以上、札は一軸に四〜七枚。`skipCommon` には、その型の作法とぶつかる共通の軸の名前。
- 新しい型は、いまある型の言い換えにしない。画面の作りか、時間の進み方か、人の関わり方が
  はっきり違うものにする（たとえば、音が主役で絵が従う型、一枚絵を描き上げていく型、
  二人で対戦する型、文字だけで組む型、道具やおもちゃとして触る型）。これは例で、
  ここから選ぶ必要はありません。fantasy-msx でできることから考えてください。

**札を入れ替える。** 残す型の `twists.json` と、`season.json` の `common` の札を、半分ほど差し替えます。

- 題に写っていた札、効いていなかった札を外す。効いていた札は残してよい。
- 札は「何を作るか」ではなく「どう作るか」を縛る。守るとコードの形が変わるものにする。
  題材を指定する札（「海を舞台にする」）は書かない。
- **札の文句が題に写りにくい言い方にする。** 名詞として持ち出しやすい語（補色、回廊、反転、
  崩壊）を避け、やり方を動詞で書く。
- 軸そのものを入れ替えてよい。同じ軸が続くと、札を替えても同じところしか変わらない。
- どの札も、fantasy-msx で実際にできることだけを書く。`prompts/api.md` に無い機能を前提にしない。

**残す型の手引きを見直す。** 段取りが固まっていた型は、`form.md` のどの文がそこへ誘導したかを
見つけて書き直す。実例（`work.ts`）は、直す理由がはっきりしているときだけ触る。

**シーズンの名前を進める。** `templates/season.json` の `season` を、今月の年月（`YYYY-MM`）にする。

## 触ってよい場所

- `templates/` の中
- `docs/seasons/<YYYY-MM>.md`（今回の記録。新しく作る）

それ以外は読むだけです。`packages/`、`prompts/`、`engine/`、`.github/`、設定ファイルは
書き換えないでください（書き換えると、このあとの検査で弾かれます）。コードやプロンプトを
直したほうがよいと思ったことは、記録の「人への提案」に書いてください。

## 確かめること

終える前に、次の二つが通ることを自分で確かめてください。通らなければ直します。

```bash
npm run typecheck
npm run check:templates
```

`check:templates` は、シーズンのデータの形を確かめ、いまの型の実例をすべてヘッドレスで
動かします。新しい実例がここで落ちるなら、その型はまだ出せません。直らなければ、
その型を出すのをやめて（`forms` に入れない）、記録に書いてください。壊れた型を
出すより、入れ替えが一つ少ないほうがよい。

一つの実例だけ試すなら `npx tsx packages/batch/src/cli.ts check templates/<id>`。

## 記録

`docs/seasons/<YYYY-MM>.md` に、次を短く書きます。プルリクエストの説明にもなります。

- **数えたこと** — 使い古されていた語、固まっていた段取り、効いていなかった札。数字つきで。
- **入れ替えたもの** — 休ませた型、足した型（どういう型か一行ずつ）、外した札と足した札の要点。
- **ねらい** — 来月の作品が、先月とどう違ってほしいか。
- **次の係へ** — 来月確かめてほしいこと（新しい型はうまく回ったか、どの札が怪しいか）。
- **人への提案** — コード、プロンプト、検査を直したほうがよいと思ったこと。無ければ書かない。
