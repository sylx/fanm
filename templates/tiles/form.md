この作品の型は **キャラクタ画面の作品**。MSX1 のゲームが画面を組んだやり方、PCG
（文字の形を自分で定義する仕組み）で作る。画面は画素ではなく、32x24 の文字コード
（768バイト）でできている。遊べるものでも、見ているだけのものでもよい。

- 画面モードは `"G3"`（SCREEN 4）、`"G2"`（SCREEN 2）、`"G1"`（SCREEN 1）のどれか。
  迷ったら G3。G3 だけスプライトが MSX2 のもの（一行ごとに色、多色の重ね）になる。
  G1 / G2 のスプライトは一枚一色で、`sprites.setMulticolor` はエラーになる。
- **このモードに `gfx`、`ctx.text`、`ctx.console` は無い**（呼ぶとエラー）。文字は
  `tiles.loadFont()` で内蔵フォントを 32〜126 に入れ、`print` で置く。ASCII だけ。
  自分の文字は 128〜255 に `tiles.define`（一色）か `tiles.defineMulticolor`（一行に
  二色まで）で作る。色 0 は黒ではなく透明で、背景色（`screen.setBackdrop`）が見える。
- **画面は毎フレーム丸ごと作り直してよい。** `new NameBuffer()` を一つ持ち、`draw` で
  `clear` → 地図・敵・点数を `put` / `print` / `putMap` / `transfer` で書き込む →
  `tiles.transfer(buffer)` で一度に送る。blitter を使わないので待ちは出ない。ビットマップの
  型の「毎フレーム描き直さない」はこの型には当てはまらない。
- **動く絵は文字の定義を書き換えて作る。** 同じ文字を使っているマスは全部一度に変わる。
  水、炎、点滅、流れる模様は `tiles.setPattern` / `setRowColors` / `setColor` で数フレーム
  ごとに書き換える。名前表（画面の文字の並び）には触れなくてよい。
- 地図と画面は同じもの。地図を `NameBuffer` に持ち、当たり判定は文字コードで取る
  （`buffer.get(x, y)`、画面から読むなら `tiles.get`）。
- G2 / G3 は画面が上中下の三つ（8行ずつ）に分かれ、それぞれ256文字を持つ（バンク。
  画面の外の下8行の分がもう一つあり、`tiles.banks` は4）。
  `bank` を省けばすべてのバンクに同じ定義が入る。256文字より多く使いたいときだけ分ける。
  G1 は8文字ごとに一組の色しか持てない（`setColor` がその組の8文字に効く）。
- 滑らかに流すなら `ctx.scroll`。名前表は32列の輪なので、入ってくる列を出ていった
  列の場所へ書く（`scroll.mask = true` で左端を隠す）。点数の行は `scroll.split` で
  止めた帯に置く。流さずに文字単位で送るなら `buffer.shift(dx, dy)`。
- スプライトは主人公と、文字の升目に乗らない速いものだけ。G3 なら主人公は多色にする
  （`sprites.setMulticolorPattern` と `sprites.setMulticolor`）。
- 操作できるなら、**誰も触らないうちは機械が自分で遊ぶ**。最初の入力が来たら人に渡し、
  しばらく触られなければまた機械に戻す。`controls` に操作を一行で書く。操作しない
  作品なら `controls` は空文字。

中身は自分で考える。掘る、迷路を追いかける、落ちてくるものを積む、箱を押す、ヘビ、
洞窟を飛ぶ、文字で描いた海や街の移り変わり。既存の作品の遊びや名前は使わない。
文字の升目（8x8）で動くことが似合うものを選ぶ。
